# Training continuation — 2026-11-01

The configured cumulative target is **1,000,000 steps**, at native **256×256**. Training resumed from the complete 193,000-step checkpoint after the prior process had stopped. The first new 193,500-step save was verified to contain finite model, EMA and optimizer tensors and saved random state. The target was subsequently extended after a clean save at 194,532 steps.

Configuration: batch 5, accumulation 2; V5 task/note flow sampling 40%, legacy interaction states 20%, ordinary examples 40%; caption augmentation 0.6; edge weight 2; text and state ROI weights 1. The stop target is independent of the cosine learning-rate decay horizon. Resume inherits the original 200,000-step horizon instead of silently increasing the current learning rate. After the horizon it remains at the existing schedule floor; extending the goal does not establish that this is the best learning rate for the entire new duration.

## Changes

- `neural/app_flow_validation.py`: eight held-out task/note transitions, evaluated in both directions under identical noise for correct/opposite English and Chinese captions. Bilingual rows referring to the same target are deduplicated; conflicting target pixels or transition geometry are rejected.
- State validation publishes the separate `app-flow-latest.json`, including its own checkpoint step. The training console shows these diagnostics.
- Training history recovers valid JSON after NUL padding, suppresses unsaved future steps after resume, handles partial records, and replaces repeated step records with the latest values.
- `tests/test_training_continuation.py` covers the extended-target learning-rate behavior and interrupted-log recovery. Run `python -m unittest discover -s tests -v` from the repository root.

## Actual quality findings

A controlled raw-main-model comparison at steps 175,000 and 193,000 used identical prompts and seed 42 at 8 and 32 sampling steps. The 193,000-step model still confused generic chat requests with editor screens and task requests with desktops. Exact held-out task/note descriptions produced more appropriate layouts and a visible draft/saved distinction, but requested text was incorrect and checkbox completion was unstable. The APP's existing 132,500-step inference snapshot was therefore retained.

Eight same-story state pairs at 193,000 steps produced 48 paired velocity evaluations. Mean wrong-minus-correct state ROI MSE was +0.00751946 in English and +0.00750085 in Chinese. The task check transition margins were much smaller: about +0.00004385 and +0.00002094. These are conditioning diagnostics, **not OCR accuracy, generated-image quality or proof that business actions succeeded**.

This report records a training configuration and completed checks, not a claim that one million steps have finished or arbitrary application UI generation is reliable. Live checkpoint files, training datasets and private runtime data are excluded from Git history. Any future model release must be separately uploaded and verified; this source update does not publish new weights.
