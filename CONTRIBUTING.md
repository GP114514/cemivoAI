# Contributing

cemivoAI is a research prototype exploring an image-based interface generated by local neural models, with an external intent planner and local Agent tools. Improvements should make that behavior more accurate, responsive and reproducible.

Useful areas include readable text and consistent layouts, prompt following, whole-frame grounding, reliable local edits, explicit failure feedback, accessible input handling and meaningful model evaluations.

## Make changes reviewable

1. Describe the concrete prompt, screen or interaction that fails and the expected visible result.
2. Keep model inference separate from training-target renderers. Do not replace an unverified neural output with a template or target image and call it a successful model sample.
3. Preserve the source frame outside a verified local edit. Check exact pixels as well as the intended control state or text.
4. Keep Agent tool success separate from drawing success. A saved document needs a real receipt and, where possible, content read-back; a screenshot alone does not prove a business action happened.
5. Report hardware, checkpoint hash/step, native resolution, seed, sampling steps and whether timings cover neural sampling or the complete request.

Tests should check observable behavior and failure paths. For interaction changes, include uncertain intent, replay/idempotence and missing-model cases when relevant. Training loss or a larger parameter count is not an image-quality acceptance test.

## Work locally

Follow [setup](docs/SETUP.md). Use separate output directories for experiments and leave another running training job's checkpoints untouched. The main CLI commands expose `--help`; the film's preview and audit commands can check composition without making APP requests.

For model or data changes, retain provenance and split information. Synthetic target contact sheets must be labeled as targets. Show actual generated images for quality claims, including failures. Do not claim general software replacement or AGI from a narrow recorded interaction.

## Keep private data out

Never commit API keys, access tokens, `.env` files, local Agent databases, private screenshots or user exports. Do not include `.venv`, caches, optimizer state or large dataset shards in a code change. Review diffs and file lists before publishing. Include only synthetic/demo interactions in public traces.

Original contributions are submitted under this repository's MIT source license. Keep applicable third-party notices and identify any new asset or dependency whose terms differ.
